# UX 수정 기록 (2026-11-06)

## 후속 요청: 반응성과 업무 흐름

- 로고의 보조 문구를 제거했다.
- 홈에서 업무를 누르면 대상·날짜·기존 확인 기준을 먼저 살펴볼 수 있다. 데스크톱은 우측 패널, 모바일은 하단 시트다. 기존 바로 처리 링크와 원래 관리 화면의 입력·저장 동작을 유지한다.
- 필터와 공통 탭의 선택 표시가 움직이고, 필터에 따라 남는 행은 위치를 옮기며 새 행은 짧게 나타난다. 숫자는 실제 값으로 수렴하며 스크린리더에는 최종 값만 제공한다.
- 지원 브라우저에서는 메뉴 크기·좌우 위치·테마에 View Transition을 사용하고, 미지원·동작 줄이기에서는 즉시 반영한다. 전환 레이어가 새 클릭을 가로막지 않게 했다.
- 화면 진입·달력 전환·버튼 누르기와 처음 스크롤로 나타나는 영역에 반응을 추가했다. 화면을 사용할 때까지 기다리게 하는 연출은 없다.
- 모바일 375px 시트의 본문은 내부 스크롤이고 하단 동작 버튼은 화면 안에 고정된다. 바깥 탭으로 닫을 수 있다.
- 메뉴·테마 연속 변경, 홈 필터, 실제 문서 항목으로의 연결, 공통 탭 방향키를 브라우저에서 확인했다. 수정 후 콘솔 오류가 없었다.
- 전체 자동 테스트는 현재 7개 파일 74개다. 기존 70개에 동작 줄이기, 미지원 API, 숫자 표시, 키보드 탭 검사 4개를 추가했다. 아래는 직전 디자인 개선 당시의 기록이다.

## 문제와 결과

검색의 바깥 클릭이 동작하지 않았고 배경 스크롤도 움직였다. 결과와 입력창이 함께 스크롤되는 긴 창이었으며 보조 글자가 작았다. 공통 대화상자를 수정해 검색·사용 안내·확인 창에 동일한 닫기 규칙을 적용했다.

- 바깥에서 누르고 바깥에서 놓은 경우에만 닫는다. 창 안에서 텍스트를 선택하다 밖으로 드래그해도 닫지 않는다.
- Escape·닫기 버튼을 지원하고 native `showModal()`의 포커스 격리와 복귀를 사용한다.
- 열려 있는 동안 배경 스크롤을 잠근다. 중첩 대화상자가 있으면 마지막 창이 닫힌 뒤 해제한다.
- 검색창은 입력부·스크롤되는 결과·키보드 안내를 분리했다. 닫을 때 140ms, 열 때 220ms의 짧은 전환을 사용한다. 동작 줄이기 설정에서는 즉시 전환한다.
- 검색은 combobox/listbox 의미, 결과 선택 상태, 방향키·Enter·Ctrl/Cmd+K, 한글 조합 중 Enter 방지, 지우기·빈 결과 복귀를 지원한다.
- 홈 필터를 `?filter=`에 저장해 새로고침 후에도 유지한다. 공통 탭은 좌우 방향키·Home·End로 이동한다.
- 직원 목록은 가로로 정보를 비교하는 목록으로 정리하고 모바일에서는 두 줄로 재배치한다. 직원 상세 경로와 기존 정보는 유지한다.
- 임시 인증 폼은 오류 발생 시 첫 번째 잘못된 입력으로 포커스를 옮긴다. 실제 인증과 서버 저장은 여전히 없다.
- 사용 안내의 자동 진행은 마우스를 올리거나 내부 요소에 포커스가 있는 동안 멈춘다. 직접 단계 이동·재생·정지가 가능하다.

## Hallmark

사용자의 요청으로 `nutlope/hallmark` v2.0.0을 설치하고 적용했다. 다음 작업자도 필요하면 `npx skills add nutlope/hallmark -g --agent codex --yes`로 설치할 수 있다. 런타임 의존성에는 추가하지 않았다.

공통 스타일·검색·UI 부품에 대한 `sloplint --scope app` 정적 검사에서 Floor 0 / Reflex 0을 확인했다. 원래 26 / 279였으며, 4개 인라인 핸들러는 공통 훅과 한글 입력을 고려한 검색 핸들러로 옮겼다. 기능 삭제가 아니다. 캐스케이드와 다크 모드 상속을 해석하지 못하는 경고는 실제 브라우저에서 확인한다.

Hallmark의 Puppeteer 렌더 검사는 이 환경에 `puppeteer-core`가 없어 실행되지 않았다. 지원되는 CUA 브라우저로 화면·키보드·반응형을 별도로 확인했다. 자동 렌더 검사를 통과했다고 주장하지 않는다. 원시 검사 기록은 로컬 `.hallmark/` 캐시에 있으며 배포·GitHub에는 넣지 않는다.

## 검증

- Vitest: 기존 업무 테스트 66개 + 모달 회귀 테스트 4개, 총 70개.
- TypeScript와 프로덕션 빌드.
- 375px: 홈·직원·급여·서류·근무·보험·기한·설정·시작·홍보 화면의 문서 가로 넘침 없음. 긴 표는 해당 영역 안에서 스크롤.
- 1440px: 밝은/어두운 홈·직원 목록·검색, 검색의 빈 상태·직원 상세 이동·포커스 복귀, 홈 필터 복원.
- 모바일 검색 바깥 탭, 메뉴 바깥 탭, 테마 전환.
- 미실시: 실제 휴대폰의 소프트 키보드, Safari/Firefox, 스크린리더 종합 검사, 실제 계정·서버 연동.

변경 전후 화면은 작업 폴더 상위 `outputs/ui-polish/`에 보관한다. 이 상대 위치는 개발 편의용이며 앱은 해당 파일에 의존하지 않는다.

독립된 최종 리뷰에서 모바일 공개 메뉴의 눈에 띄는 가로 스크롤바 1건을 발견했다. 메뉴 간격을 줄여 375px에서 네 항목이 모두 들어가도록 수정했고, 실제 메뉴의 scrollWidth와 clientWidth가 같은 것을 확인했다. 데스크톱과 모바일의 주요 화면 및 320px 헤더에서 조작 요소가 잘리지 않는 것도 확인했다.
